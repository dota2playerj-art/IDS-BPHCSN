# IDS-BPHCSN AI WORKFLOW

Version: 1.0

---

# Purpose

This document defines the official workflow for using Artificial Intelligence during the development of the IDS-BPHCSN project.

Its goals are:

- Produce consistent results
- Reduce AI credits
- Reduce repeated prompts
- Maintain documentation
- Improve software quality
- Keep every AI assistant synchronized

---

# AI Philosophy

Artificial Intelligence is a project assistant.

AI does not replace human decision making.

Every AI-generated output must be reviewed before implementation.

Always prioritize the approved Capstone Proposal over AI suggestions.

# Recommended Prompt Structure

Every request should follow this format.

Context

↓

Objective

↓

Requirements

↓

Constraints

↓

Expected Output

Example

Context

Continue the IDS-BPHCSN project.

Objective

Generate the Patient Records page.

Requirements

Follow all uploaded documentation.

Constraints

Bootstrap 5

Desktop only

Expected Output

Professional UI mockup.

---

# Saving AI Credits

Do NOT repeatedly explain the project.

Upload documentation once.

Reference existing files instead of rewriting instructions.

Reuse approved prompts.

Avoid restarting conversations unless necessary.

Group related tasks together.

Generate complete modules instead of isolated components.

---

# AI Session Rules

Examples

Coding Session

Testing Session

# Prompt Management

Never delete prompts that produced good results.

Store successful prompts inside the Prompt Library.

Improve prompts over time.

Document why a prompt worked well.

---

# Quality Assurance

After every AI output ask:

Is it correct?

Is it consistent?

Does it follow Bootstrap?

Does it match the UI Design System?

Does it follow the Capstone Proposal?

Would a real user understand it?

---

# Managing Long Conversations

If an AI conversation becomes too long:

Create a new conversation.

Upload the documentation again.

Provide a brief summary of progress.

Continue from the latest approved state.

Avoid rebuilding context from memory alone.

---

# Version Control

Every major AI-generated output should be saved.

Examples

UI v1

UI v2

Database Schema v1

Dashboard Revision

Patient Module Revision

Keep previous versions.

Do not overwrite important work.

---

# File Naming Convention

Use clear names.

Examples

Login_v1.png

Dashboard_v2.png

PatientRecords_v1.png

Inventory_UI_v1.png

Avoid generic names like

image1.png

new.png

finalfinal.png

# AI Limitations

AI can make mistakes.

AI can misunderstand requirements.

AI may generate inconsistent designs.

AI may invent features.

Always verify outputs.
