{#- Stated beside the figures rather than left to be inferred: a refusal aimed at a username that does not exist writes no row, because audit_logs.user_id is NOT NULL and foreign-keyed to a real account. And under no circumstance is a supplied password recorded -- see the module note in routes/auth.py. #}
A refused attempt records the account it was aimed at, the moment and the address — never the password that was supplied. An attempt against a username that does not exist is not recorded at all: there is no account for the entry to belong to. Signing out is not recorded either, so these are sign-in counts rather than session counts. A deactivated account is refused even when the password presented is correct, and its entry says which it was — but the person at the login form sees the same message a wrong password gets, so the form cannot be used to discover which accounts exist or which have been switched off.
