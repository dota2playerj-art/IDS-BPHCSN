{#- The page a signed-in Doctor, Health Center Staff or Barangay Official sees while an Administrator has the system closed. Returned by utils/security.py's _maintenance_response(), with a 503, from the same guard that admits every other request. WHY IT DOES NOT EXTEND base.html, WHICH EVERY OTHER SCREEN DOES. base.html draws the sidebar: Patient Records, Medicine Inventory, Patient Queue, the low-stock badge, the search box across the top. Every one of those is a link this person cannot follow right now. A page whose whole message is "you cannot use the system at the moment", wrapped in a full working navigation, invites exactly the clicking-around the message is asking them not to do -- and each click would come back here, which reads as the application being broken rather than deliberately closed. So this is a standalone page, and it is the second one in the project built that way. The first is login.html, for the same reason: there is nothing to navigate to yet. It borrows that page's shape on purpose -- the same teal ground, the same centred card -- because the two are the only screens in this system that say "not right now", and somebody who has seen one should recognise the other. WHAT IT DOES NOT SAY. It does not guess when the system will reopen. Nothing in this project knows: there is no scheduler, no window recorded anywhere, and no field an administrator filled in to say how long they would be. A time printed here would be the sort of invented figure this screen's own Settings pane has spent three passes deleting, and it is the one thing a reader would act on. "Shortly" is the honest length of an interval nobody measured. It also does not name the administrator who closed it. That is in the audit trail, where an Administrator can read it, and putting it here would send a health worker to knock on one particular door -- which may be the wrong one, since any Administrator can reopen the system. #} IDS-BPHCSN | Maintenance
